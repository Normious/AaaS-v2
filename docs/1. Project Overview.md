# 1. Project Overview

## What is AaaS v2?

Hardened, self-hosted identity provider (Rust + Axum). One service issues and verifies credentials for the whole 30-service ecosystem (Day 30 of the challenge; rebuild of Day 1's TypeScript AaaS). Full design doc: [`AaaS-v2.md`](../AaaS-v2.md).

## Core capabilities

- Register + email verification (24 h tokens, SHA-256 at rest)
- Login with time-based one-time passwords (TOTP) 2FA: challenge-token step plus single-use backup codes
- Access tokens: EdDSA Ed25519 JWTs (15 min). Services verify **locally** with the public key: no round-trip to AaaS
- Refresh tokens: rotating, single-use, **theft detection** (reuse kills the whole session)
- Multi-device sessions: list, per-device revoke, max-N enforcement
- Password change (revokes all sessions) + secure reset (1 h tokens, no email-existence leak)
- Email change with re-verification
- Account lockout (5 fails → 15 min) + per-IP / per-account rate limiting
- Append-only audit log + `GET /me/audit-log`
- `X-Request-ID` propagation, JSON structured logs

## Technology stack

| Layer | Choice |
|---|---|
| Language / framework | Rust 1.80+ / Axum 0.7 / Tokio |
| Passwords | `argon2` Argon2id (OWASP params, configurable) |
| JWT | `jsonwebtoken` EdDSA + `ed25519-dalek` |
| 2FA | `totp-rs` (RFC 6238, SHA1/6-digit/30 s) |
| DB | `sqlx` + SQLite (WAL, FK on) |
| Email | `lettre` (SMTP, best-effort background sends) |
| Validation | `validator` derive macros |
| Observability | `tracing` JSON + `X-Request-ID` |

## Getting started

```bash
mkdir -p secrets
openssl genpkey -algorithm Ed25519 -out secrets/jwt-private.pem
openssl pkey -in secrets/jwt-private.pem -pubout -out secrets/jwt-public.pem
cp .env.example .env   # SMTP off by default; good for local
cargo run              # → http://localhost:3000/health
```

Docker: `docker compose up --build -d` (31 MB image). Windows Git Bash: use compose, not hand-rolled `docker run -v` (MSYS mangles bind paths).
